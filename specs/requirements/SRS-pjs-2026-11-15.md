# Software Requirements Specification: PJS

> [!abstract]
> System-level functional requirements for PJS (workspace 0.7.0), reverse-engineered from the verified capability specs. Each requirement states the current behaviour, the owning spec (which holds the detailed EARS requirements and acceptance criteria) and its verification state as of 2026-11-15. "Shall" marks behaviour that exists in code; gaps are listed in section 6.

## 1. Introduction

- Purpose: single traceable index from business objectives ([[BRD-pjs-2026-11-15]]) to capability specs and quality targets ([[NFR-pjs-2026-11-15]]).
- Product: crates `pjson-rs` (core) and `pjson-rs-domain`, WASM bindings (`crates/pjs-wasm`), TypeScript client (`crates/pjs-js-client`), demo and bench crates.
- Wire format: draft in [`docs/architecture/SPECIFICATION.md`](../../docs/architecture/SPECIFICATION.md); as-built form documented in [[045-priority-stream-planning/spec|045]] and [[067-websocket-wire-protocol/spec|067]].

## 3. Functional Requirements

Status: done = implemented and verified; part = partially implemented; gap = documented but not implemented.

### Protocol and domain

#### SR-001 Domain model
The system shall represent frames, streams, priorities, identifiers, JSON data, paths and schemas as validated domain types in `pjs-domain`. Source: BO-001, BO-005. Spec: [[042-domain-crate-contract-and-value-objects/spec|042]], [[043-domain-schema-depth-guard-wire-encoding/spec|043]], [[044-domain-entities-events-priority-heuristic/spec|044]]. State: done.

#### SR-002 Priority planning
The system shall split a JSON document into a skeleton frame, prioritized patch frames and a completion frame, with arrays chunked at lower priority. Source: BO-001, BO-002. Spec: [[045-priority-stream-planning/spec|045]], [[031-array-duplication-reconstruction/spec|031]]. State: part (see 6).

#### SR-003 Reconstruction
The system shall rebuild the original document by applying frames in order. Source: BO-001. Spec: [[046-json-reconstruction/spec|046]]. State: done.

#### SR-004 Non-finite numbers
The system shall reject NaN and infinite floats when constructing and deserializing `JsonData`. Spec: [[019-jsondata-nan-handling/spec|019]]. State: part (public `Float` variant can still hold NaN).

#### SR-005 Session lifecycle
The system shall manage stream sessions through a state machine with stream creation, start, completion, failure and expiry. Spec: [[053-stream-session-aggregate/spec|053]], [[055-application-commands/spec|055]]. State: done.

### Parsing

#### SR-006 Parsing
The system shall parse JSON with a bounded zero-copy parser and, behind `partial-parse`, a partial parser; SIMD acceleration is delegated to `sonic-rs` and enabled by `simd-auto`/`simd-avx512`. Spec: [[038-zero-copy-lazy-json-parser/spec|038]], [[039-partial-json-jiter-parser/spec|039]], [[041-simd-features-and-global-allocator/spec|041]]. State: part (partial parser has no production caller; earlier hybrid parser removed, see [[001-simd-backend-implementation/spec|001]], [[006-sonic-rs-primary-parser-path/spec|006]]).

#### SR-007 Buffer pooling
The system shall provide a reusable aligned buffer pool. Spec: [[040-buffer-pool-aligned-alloc/spec|040]]. State: done.

### Compression and security

#### SR-008 Schema compression
The system shall compress JSON frames with schema-aware strategies (dictionary, delta, RLE, hybrid). Spec: [[048-schema-compression-strategies/spec|048]]. State: done.

#### SR-009 Streaming frame compression
The system shall compress and decompress frames with resource guards on decode. Spec: [[047-streaming-frame-compression/spec|047]]. State: done.

#### SR-010 Byte compression
The system shall offer Deflate/Gzip/Brotli and zstd (with trained dictionaries) byte codecs with decompression-bomb protection. Spec: [[049-secure-byte-compression/spec|049]], [[002-real-compression-algorithms/spec|002]], [[011-zstd-dictionary-compression/spec|011]]. State: part.

#### SR-011 Bomb and rate protection
The system shall detect compression bombs and rate-limit clients per IP. Spec: [[050-compression-bomb-and-rate-limiting/spec|050]]. State: done.

#### SR-012 Configurable limits
The system shall expose validated security limits (size, depth, cardinality) via typed configuration. Spec: [[051-security-limits-and-validated-config/spec|051]], [[018-config-validation-startup/spec|018]]. State: part (limits enforced by `ZeroCopyParser`, zero and inconsistent values rejected, #613, #614; some config fields still unread).

### Application and infrastructure

#### SR-013 CQRS
The system shall expose commands and queries through handlers that depend only on domain ports. Spec: [[055-application-commands/spec|055]], [[056-application-queries-dto/spec|056]], [[052-domain-gat-ports/spec|052]]. State: done (one known layering leak, see [[architecture-baseline]]).

#### SR-014 Storage adapters
The system shall provide in-memory repositories, frame store, event publisher and dictionary store. Spec: [[057-in-memory-repositories/spec|057]], [[058-event-metrics-dictionary-adapters/spec|058]]. State: part.

#### SR-015 Pagination
The system shall paginate session listings. Spec: [[008-cursor-pagination-active-sessions/spec|008]]. State: part (offset pagination only; cursor not implemented).

### Transport

#### SR-016 REST API
The system shall serve the REST routes with a typed error to status mapping. Spec: [[060-http-rest-api/spec|060]], [[017-axum-error-http-status-mapping/spec|017]]. State: done.

#### SR-017 Streaming responses
The system shall stream frames as NDJSON or SSE chosen by RFC 9110 `Accept` negotiation. Spec: [[063-http-streaming-negotiation/spec|063]], [[015-batch-stream-ndjson-format/spec|015]], [[035-streaming-module-unreachable/spec|035]], [[036-accept-header-negotiation-crate/spec|036]]. State: done.

#### SR-018 Middleware
The system shall apply request limits, timeouts, security headers, rate limiting and API-key authentication. Spec: [[061-http-middleware-stack/spec|061]], [[007-http-auth-middleware/spec|007]], [[026-apikey-config-debug-redaction/spec|026]]. State: part (JWT layer not wired).

#### SR-019 Connection protection
The system shall enforce connection count, per-IP, header-read and duration limits in `serve_with_limits`. Spec: [[062-http-serve-connection-limits/spec|062]]. State: done.

#### SR-020 Graceful shutdown
The system shall drain in-flight streams on shutdown. Spec: [[037-graceful-shutdown-serve-with-limits/spec|037]]. State: implemented (#590).

#### SR-021 WebSocket
The system shall bind each session to its owning connection, deliver frames only to the owner, and cap messages, frames, sessions and bytes. Spec: [[066-websocket-server-transport/spec|066]], [[067-websocket-wire-protocol/spec|067]], [[068-websocket-client/spec|068]], [[029-websocket-stream-session-binding/spec|029]]. State: part.

#### SR-022 Metrics
The system shall expose Prometheus metrics behind the `metrics` feature. Spec: [[065-http-prometheus-metrics/spec|065]], [[009-realtime-metrics-observability/spec|009]]. State: part.

### Clients

#### SR-023 WASM bindings
The system shall provide browser/Node bindings with enforced security limits and typed TypeScript definitions. Spec: [[070-wasm-bindings-api/spec|070]], [[071-wasm-security-limits/spec|071]], [[072-wasm-packaging-targets/spec|072]], [[010-wasm-typescript-type-generation/spec|010]], [[033-wasm-security-config-shared-reuse/spec|033]]. State: done.

#### SR-024 TypeScript client
The system shall provide a TypeScript client with HTTP, SSE, WebSocket and WASM transports. Spec: [[073-js-client-core/spec|073]], [[074-js-client-wasm-integration/spec|074]], [[020-ts-client-wasm-api-sync/spec|020]], [[027-wasm-backend-node-init/spec|027]], [[030-wasm-loader-esm-cjs-mismatch/spec|030]]. State: part (endpoint and priority mismatches with the server).

### Engineering support

#### SR-025 Verification infrastructure
The repository shall provide benchmarks, fuzz targets, demo servers, CI and release pipelines. Spec: [[075-bench-suite/spec|075]], [[076-fuzz-targets/spec|076]], [[077-demo-servers/spec|077]], [[078-ci-pipeline/spec|078]], [[079-release-pipeline/spec|079]], [[021-bench-crate-workspace-isolation/spec|021]], [[022-ci-js-client-enforcement/spec|022]], [[028-pjs-demo-workspace-build/spec|028]]. State: done.

## 6. Known Gaps

> [!question] Open items surfaced by verification
> - [ ] SR-002: `StreamerConfig` fields unused, `max_patch_size == 0` panic, wire form differs from the draft ([[045-priority-stream-planning/spec|045]]).
> - [x] SR-012: array/object/string limits enforced by `ZeroCopyParser`, zero limits rejected (#613, #614).
> - [ ] SR-018: JWT layer not reachable from router constructors ([[061-http-middleware-stack/spec|061]]).
> - [x] SR-020: graceful shutdown implemented (#590); the terminal SSE/NDJSON frame is appended at drain expiry (#625).
> - [ ] SR-024: JS client endpoints and priority scale differ from the Rust server ([[073-js-client-core/spec|073]]).
> - [x] `pjs-domain` is `std` only; the unsupported `no_std` mode and the `std` and `wasm` features were removed (#606), see [[042-domain-crate-contract-and-value-objects/spec|042]].
> - [ ] Package naming: npm `@pjson/wasm` (published) versus `pjs-wasm` in docs.
